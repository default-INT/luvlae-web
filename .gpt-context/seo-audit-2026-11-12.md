# SEO audit of luvlae.com and remediation plan — 2026-11-12

Source: live check of `https://www.luvlae.com` on 2026-11-12 (14 sitemap URLs plus one missing URL), mapped to the code in `apps/web`. Not verified: field Core Web Vitals, Search Console/GA4 data, Google indexing, Google's rich-result validator. Related notes: [SEO requirements](seo-requirements.md), [direct-sales audit 2026-10-27](seo-audit-2026-10-27.md), [how-to investigation](seo-how-to-audit-2026-10-30.md).

## Summary

Foundation is sound: single HTTPS `www` host (308 from apex/http), robots.txt and sitemap on the canonical host, all 14 URLs return 200, self-referencing canonicals, one H1 per page, real 404 with `noindex`, `Organization`/`WebSite`/`BreadcrumbList`/`Product`+`Offer` JSON-LD matching the visible price (USD 19.99). Estimated score 82/100. One defect is critical; the rest is metadata quality and growth work.

## Corrections to the first audit

- **H1 "BerberinePatches" was a false positive.** It came from stripping tags in the audit script. Home H1 has an `aria-label` with a space and other headlines use `<br>` via `LineBreakText`. No action, only a manual screen-reader/accessibility-name check if desired.
- **`no-store` applies only to `/` and `/products/berberine-patches`**, not to all pages. Both are `force-dynamic` because they read the live offer (price/stock) — see `app/(default)/page.tsx:9`, `app/(default)/products/berberine-patches/page.tsx:7`, and the global header in `next.config.ts:15`. Other pages are static: `s-maxage=31536000, stale-while-revalidate`.
- **Empty `alt=""` (8 on `/about-product`, 7 on the product page)** are decorative images and icons; this is correct, not an issue.

## Plan

### Phase 0 — critical fix (≈ 0.5 day)

**Status 2026-11-12: implemented locally, not deployed.** `defaultOgImage` in `src/shared/config/site/site.ts` (existing 1280×853 WebP) is used by `getInformationMetadata` and the About page; `tests/storefront-seo.test.ts` checks that OG files exist. A branded 1200×630 image is still to be made. Production still serves the 404 until deployed.

1. **Fix OG image path (finding 1).**
   - Short term: point both places to an existing file, e.g. `/images/luvlae-berberine-woman-with-patches.webp` (1280×853, already used by `/about-product` with those dimensions).
   - Preferred: add a branded 1200×630 JPG/WebP to `apps/web/public/images/` and use it as one shared constant (e.g. in `src/shared/config/site`) so `getInformationMetadata`, `about/page.tsx` and the root default share one source.
   - Correct `width`/`height`/`alt` to the real file. Alt text must describe the actual image; no GLP-1 wording.
2. **Add a regression test** in `apps/web/tests/storefront-seo.test.ts`: every `openGraph.images[].url` produced by the metadata functions must exist in `apps/web/public`. This prevents a repeat of the 2026-10-10 "missing JPG" problem.
3. Acceptance: `curl -I` on each OG URL returns 200 `image/*`; the five pages show correct previews in a social debugger.

### Phase 1 — metadata quality (≈ 1 day)

**Status 2026-11-12: implemented locally, not deployed.** `metaTitle` added to `InformationPageContent`; new titles/descriptions applied (how-to, safety, science, FAQ, contact, home, product, ingredients); legal pages (contact, shipping, returns, terms, privacy) now set `defaultOgImage` and `summary_large_image`. A test in `tests/storefront-seo.test.ts` enforces title 40–60 and description 110–160 characters for information pages. Home, product, ingredients and contact lengths were set by hand and are not covered by that test. Re-run the live audit after deploy.

4. Add optional `metaTitle` to `InformationPageContent` in `pages.ts` and use it in `getInformationMetadata` (fallback: existing `title`). This avoids changing visible H1/eyebrow copy.
5. Proposed titles (50–60 characters including ` | Luvlae`; adjust after label verification):
   - How-to: `How to Use Berberine Patches: Apply & Remove | Luvlae`
   - Safety: `Berberine Patch Safety: Skin Care & Precautions | Luvlae`
   - Science: `Berberine Patch Science: What Research Covers | Luvlae`
   - FAQ: `Berberine Patches FAQ: Use, Skin Care & Buying | Luvlae`
   - Contact: `Contact Luvlae Support: Orders, Shipping, Returns` (edit in `en.yaml`)
6. Rewrite descriptions to 120–160 characters, factual, no outcome promises and no unconfirmed wear time/ingredients: FAQ, Ingredients, Product, Home, Science (shorten). Keep copy in `en.yaml`/`pages.ts`, per project rules.
7. Default OG/Twitter image and `twitter:card=summary_large_image` in the shared layout metadata for pages that set none (finding 5).
8. Acceptance: re-run the audit script; all titles 40–60 characters, descriptions 120–160, no page without OG image except `noindex`/admin routes.

### Phase 2 — crawl signals and structure (≈ 1 day)

9. **Sitemap `lastmod` (finding 4):** keep a manual map `path → ISO date` next to the page config and update it only when the page content actually changes (or derive from git commit date at build time). Never use the request/build time.
10. **`/about-product` decision (finding 7):** after 4–6 weeks of GSC data compare it with `/` and `/products/berberine-patches`. If it competes for the same queries, either differentiate the intent, canonicalize to the product page, or set `noindex`. Until data exists, leave as is.
11. **Breadcrumbs/JSON-LD:** add `BreadcrumbList` to `/about-product` only if the page shows visible breadcrumbs.
12. Validate all JSON-LD with Google's Rich Results Test and Schema.org validator after deploy.

### Phase 3 — performance and caching (decision needed, ≈ 1–2 days)

13. Measure first: PageSpeed/CrUX for `/` and `/products/berberine-patches` (mobile LCP, INP, CLS). The doc claims about TTFB are single-sample.
14. Options for home `no-store`, weigh against the "price reaches HTML on next request" requirement:
    - (a) keep as is if CWV are good;
    - (b) short revalidate/CDN cache (e.g. 60 s) accepting delayed price/stock freshness in HTML and JSON-LD;
    - (c) static shell with server-rendered offer fragment. Requires an architecture change; read `architecture.md` before choosing.
15. Hero image: confirm the served format; convert PNG source to WebP/AVIF and cap `sizes`/widths if the mobile variant is oversized.

### Phase 4 — content and trust (continuous; gated)

16. Build the planned pages from [seo-requirements](seo-requirements.md) in this order, each with a distinct intent: `/berberine-patches-vs-capsules`, `/guides` hub and articles (what are berberine patches, how to read the label, oral vs transdermal research). No near-duplicate keyword-permutation pages.
17. Add `Article` schema, byline, reviewer, sources and a real "last reviewed" date on Science/Safety/How-to — only with real people and real reviews. `FAQPage` markup is optional: Google restricts FAQ rich results, so treat it as a minor AI/semantic aid, not a ranking feature.
18. Extend Product JSON-LD with `hasMerchantReturnPolicy` (30-day guarantee) and `shippingDetails` only after confirming they match `/returns` and `/shipping` text exactly.
19. Measurement: verify the Domain property in Search Console, submit the sitemap, track non-brand impressions/CTR per page, review pages after 4–6 weeks; keep GA4 ecommerce events per the 2026-10-27 note.

## Guardrails (from existing notes)

- Do not add `AggregateRating`/`Review` markup from the illustrative homepage reviews or Amazon.
- Keep claims at "supports" level; no GLP-1/Ozempic equivalence, appetite-suppressant, fat-burning or disease claims; no oral-to-patch evidence transfer.
- Do not publish exact ingredients, amounts, placement or wear time beyond what the verified label supports (see [product note](products/luvlae-berberine-patches.md)); the Ingredients/How-to/Safety/Science TODOs in `pages.ts` remain open.
